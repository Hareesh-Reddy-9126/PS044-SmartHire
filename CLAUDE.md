# PS044-SmartHire

## Project Rules

- This is a new project. Do not revive or copy old implementation.
- Prefer simple, maintainable solutions.
- Do not add dependencies unless justified.
- Never expose secrets, credentials, API keys, or environment files.
- Validate changes with tests before considering work complete.
- Prefer incremental changes over large rewrites.
- Keep documentation synchronized with implementation.
- Use project skills when relevant.
- Follow security-first practices for authentication, authorization, input validation, secrets, and API design.
- Inspect the repository before creating or changing files.
- Do not make architectural changes without explaining the trade-offs.

## Development Workflow

1. Understand the requirement.
2. Inspect the relevant code and configuration.
3. Plan the smallest correct change.
4. Implement.
5. Test.
6. Review for security and regressions.
7. Report exactly what changed and what was verified.
